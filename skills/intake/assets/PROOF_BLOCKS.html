Every block below is the same part: a thin head, a body, a quiet foot — the .mod skeleton — wearing a modifier class that gives it its job. It is a convention with defaults, not a closed set — a new block is additive.

§ 01

The .mod skeleton — head · body · foot

One card skeleton underlies every block. A block = one skeleton + one modifier class. The head carries identity and affordances; the body carries the block's actual content; the foot carries honest provenance at rest, with scaffolding facts folded behind a ⓘ disclosure. The three regions are annotated on the specimen below.

§ 03

The static freshness dot — color is never the only channel

Any hand-authored freshness dot in a static block MUST carry three things: role="img", a bucket-word aria-label, and a non-color shape channel. The shape below ramps by fill fraction — filled → three-quarter → half → ring → dashed — so the bucket reads without any hue at all.

Fresh
filled · < 24h
Recent
three-quarter · < 7d
Moderate
half · < 30d
Stale
ring · > 30d
Unknown
dashed · no date

Why: a reader with color-vision deficiency, a grayscale print, or a screen reader must all get the bucket. Hue (from the --fresh … --unknown tokens) is the fast channel for everyone else; the fill-fraction shape and the aria-label are the honest fallbacks. Never emit a bare colored <span> dot. Legend (§ colophon) travels with any page that uses these hues — §INV_PROVE_FAITHFUL_PRESENTATION.

The premise

Color is never decorative here — every hue encodes a verifiable fact, and always carries a text label beside it.

Freshness dots bucket real recency; verdict chips carry their ruling in words; provenance is spelled out. Remove the color and the page still reads.
